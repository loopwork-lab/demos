    What production looks like

    The demo is the core loop. Around it, a real deployment needs:

    • Inbox and Drive watcherA shared order inbox (Gmail or Outlook) and a Drive folder are watched. Attachments are split out, and each order is processed within a minute of arriving.
    • Review screenThe side-by-side view above becomes the reviewer's tool: correct a line, approve, or reply to the customer. Each correction is saved for that account, so it's automatic next time.
    • Your spreadsheets, mergedI combine your customer and product sheets into one account table and flag duplicates and conflicts for you to settle. Your team keeps editing it as a spreadsheet, so rules change without a developer.
    • Accuracy check before go-liveA few hundred of your real past orders with known correct answers. Every field's accuracy is measured before anything auto-approves, and again after every prompt change.
    • Documentation and handoverA one-page reviewer guide, a how-to for adding an account or rule, a recorded walkthrough, and code docs.
    • Audit logEvery order keeps the original file, Claude's raw output, each rule result, and who approved it and when.
    • Running costThe fixed part of each request (instructions, catalog) is cached, and backlogs go through the Batch API at half the per-token price. Cost per order gets measured on your orders, not estimated here.

    How it works

    Claude reads the documents. Plain code, working from your own account and product spreadsheets, makes every decision.

    What Claude does

    • Reads any format: typo-filled emails, forwarded threads, PDF purchase orders, odd spreadsheet exports, chat logs.
    • Copies the customer, PO number, date and each line exactly as written, into fixed fields rather than free text.
    • Follows the conversation: "actually make it 4", "same as last time but double the flour", quoted old orders to ignore.
    • Suggests catalog SKUs for each line, and lists every option when the wording is ambiguous.

    What code does

    • Finds the account: exact name, then known alias, then the sender's email domain (from the real email header, not from the text), then close spelling.
    • Checks every SKU exists and converts units with real pack sizes (12 tins = 2 cases; 72 lb = 2 cases).
    • Prices from the account's tier. Applies its rules: PO required, minimum order, approval limits, route days, pallet and driver notes.
    • Approves the order, or holds it with a reason. The same input always gives the same decision.

    If Claude suggests a SKU that isn't in the catalog, code drops it. If a PO has prices printed on it, code checks them against your price list and never copies them. The model can't make up a product, a price or an approval.
